# v2.2.0 Proof Notes

This page records the release-specific evidence required for the cache, watch,
and multiline-authoring changes. It is a reproducible proof surface, not a
performance guarantee.

## Architecture Decisions

- Cache registries are owned by the active `Runtime` and weakly referenced, so
  entries survive reruns but disappear with the app process and cannot leak to
  an unrelated app runtime.
- A cached function defined during a script pass keeps a weak reference to its
  owning runtime for contextless worker calls. Shared decorators with no owner
  fail during an active app instead of guessing, while standalone decorators
  outside `stui run` retain their isolated process fallback.
- Runtime-owned registries make resource backreference cycles collectible when
  an app runtime is no longer referenced.
- `cache_data` stores an in-memory pickle and restores a new value on each hit;
  `cache_resource` intentionally returns the same object identity.
- A changed watched Python source clears both cache namespaces for that runtime
  and evicts only local project modules before rerun.
- Watch mode polls content-aware source signatures. It ignores unrelated files,
  virtual environments, repositories, bytecode caches, and build output.
- `text_area` uses Textual's first-party multiline widget. Enter inserts a
  newline and Ctrl+Enter applies the value.
- Tabs were deferred because inactive-content execution, nested state, focus,
  forms, and narrow-terminal behavior do not yet have a small proven contract.

## Edge Cases

| Area | Proof expectation |
| --- | --- |
| Cache key | Bound positional/keyword calls normalize to the same key; keyword order does not matter. |
| Mutation | Mutating a `cache_data` hit cannot poison later reads. |
| Identity | A `cache_resource` hit preserves object identity. |
| Errors | Exceptions and unsupported `cache_data` results are not cached. |
| Lifetime | Normal reruns retain cache entries; process exit, clear, TTL, LRU eviction, code changes, and watched-source changes invalidate as documented. |
| Isolation | Same-named functions and modules in unrelated app runtimes do not share state. |
| Worker ownership | Script-defined wrappers keep their runtime; ambiguous unowned workers fail instead of crossing app scopes. |
| Runtime lifetime | Resource backreferences do not keep an otherwise unreachable runtime alive. |
| Watch saves | In-place writes, atomic replacement, deletion/recreation, and rapid writes are coalesced safely. |
| Recovery | A temporary helper syntax error renders an error while the watcher stays alive; a later valid save recovers. |
| Text area | Newlines, Ctrl+Enter apply, callbacks, forms, disabled state, Unicode, max length, focus, and narrow rendering are tested. |

## Exact Commands

```bash
python3.11 -m pytest tests/test_cache.py tests/test_watch_mode.py \
  tests/test_module_isolation.py tests/test_text_area.py
python3.11 scripts/benchmark_v220.py
python3.11 scripts/verify_v220_project.py
python3.11 scripts/verify_v220_project.py \
  --wheel dist/stui_terminal-2.2.0-py3-none-any.whl
```

The external-project validator creates an exclusive mode-`0700` temporary
workspace, runs
`stui check --strict --repeat 3`, drives the runtime through a Textual harness,
and launches the exact installed `python -m stui run app.py --watch` command in
a PTY. It edits `helpers.py`, observes changed output, introduces a syntax
error, verifies the process remains alive, fixes the helper, and observes
recovery. The PTY is ended with a controlled signal after the proof so printable
characters are not injected into the focused text area.

Supplying `--workdir` is supported for debugging, but the destination must not
already exist and is created atomically with private permissions. The verifier
never resolves and recursively deletes a pre-existing fixed path.

## Advisory Timing Checkpoint

On the release maintainer's macOS Python 3.11 environment, a local pre-release
checkpoint recorded:

- 51 runtime passes with one cache miss and 50 hits; the wrapped function
  executed once;
- 17.3566 ms median complete cached rerun for the deliberately small probe;
- 0.0388 ms median unchanged watch poll across 500 samples and two tracked
  source files.

These numbers include full script execution and local machine noise. They are
not release thresholds and should not be interpreted as a universal speedup.
Correctness, isolation, recovery, and reproducibility are the release gates.
