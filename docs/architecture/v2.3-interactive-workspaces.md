# v2.3 Interactive Workspaces Architecture

Status: accepted for implementation on `release/v2.3.0-interactive-workspaces`.

## Constraints

- Preserve every v2.2 stable API and the top-to-bottom script execution model.
- Keep all new state process-local and owned by one `Runtime`.
- Do not add browser, server, websocket, shell-execution, heavy dataframe, or
  plotting dependencies.
- Treat paths as local user input, not as uploads or a security sandbox.
- Diagnostics expose structure and counters, never session values, cache
  arguments/results, environment secrets, or file contents.

## Tabs

`st.tabs` is represented as one parent element containing ordered tab child
blocks. Every context block executes during the normal script pass. Only the
active block is mounted, so hidden widgets cannot receive focus or events.

The active index uses the existing widget-key and `session_state` machinery.
Changing tabs follows the existing interaction contract: update state, run the
callback, rerun the script, and render the new active block. This costs one
normal rerun but keeps keys, callbacks, forms, and error rollback coherent.
Nested tabs must either share this model with deterministic keys or fail with a
clear `ApiUsageError`; silent partial nesting is not acceptable.

## Path Input

`st.path_input` is a text-first widget. Its value is normalized without reading
the selected target. Relative values and `root` are resolved from the app
script directory, `~` is expanded, environment variables are not expanded, and
the returned value is an absolute string. `root` is an initial browse/resolve
location, not a sandbox boundary.

Validation happens on commit through the normal widget pipeline. `kind`,
`must_exist`, and extension filters produce readable API/user errors. A browse
overlay may ship only if it is bounded, non-recursive by default, and reliable;
the text-plus-validation workflow is the required contract.

## Interactive Data Table

`st.data_table` reuses the existing table normalization rules but is a distinct
interactive element. Its first contract supports no selection or one selected
source-row index. It returns `int | None`, never a mutable row object. Keyed
selection uses `session_state`; changing data preserves a still-valid source
index and otherwise resets it to `None`.

Only the mounted visible rows are interactive. Arrow keys move the cursor;
Enter/Space commits selection through the existing state/callback/rerun path.
`max_rows` and `max_cols` remain display limits, not mutations of source data.

## Inspect And Diagnostics

`stui inspect` runs the same `Runtime` and validation path as `stui check`, then
adds versioned structural diagnostics: timings, element/widget/key counts,
nesting summaries, imported local module paths, watch paths, and aggregate
cache counters. Paths are normalized but file contents and runtime values are
never serialized.

Cache decorators may expose aggregate `cache_info()`/`stats()` counters. Counts
stay runtime-scoped and never include argument keys or values. The command
palette is limited to built-in UI actions; it cannot execute shell commands,
Python expressions, or user-supplied command strings.

## Narrow Terminals And API Status

Tabs, path input, and data tables must wrap, truncate, or stack rather than
overflow. Keyboard behavior is the baseline; mouse behavior is additive where
Textual's harness proves it. New APIs start post-v2 experimental. Existing
experimental APIs graduate only after signature, state, installed-wheel, and
real-terminal proof all pass.
